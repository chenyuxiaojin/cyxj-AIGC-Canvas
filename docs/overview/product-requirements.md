# 小陈的画布：产品需求与验收标准

本文是当前个人桌面版的统一需求依据，汇总用户已确认的决定。需求是目标，不代表功能已经完成；施工状态与证据分别记录在 [待测试](../progress/pending-test.md)、[TODO](../progress/todo.md) 和专项验收报告中。

PRD 随用户目标更新，用户后续明确指令优先；现有实现、接口白名单和历史限制不能反过来限定用户需求。新决定在此更新一次，其他文档引用；上游 README、历史报告及旧技术栈描述不能覆盖本文件。协作与代码规范见根目录 [AGENTS.md](../../AGENTS.md)。

## 1. 产品定位

为小陈在 macOS 上制作 AI 内容提供一个本地创作工作台：把故事、人物、场景、分镜、图片、视频、音频和创作对话放在同一张可编辑画布中，能持续修改、保存、交给 Agent 操作并导出携带素材的项目。

核心使用方式：**用户提出创作目标，电脑通过接口完成操作，用户在画布上查看和迭代成果。** 用户负责表达意图、判断结果和手动修改；Agent 负责读取现状、执行操作并回填结果。双方操作同一张画布，用户的最新修改必须能被 Agent 读取并用于后续工作。

程序操作能力是产品的核心交付要求。画布已有的创作操作都应提供 CLI / API / MCP 入口；需要用户代为点击才能继续的创作环节，应登记为接口、执行能力或状态反馈缺口。手动编辑用于用户接手和迭代，保留完整能力。

用户关注实际可用的创作流程，界面采用简洁中文，不要求用户理解后端、协议或数据库。Agent 应承担实现和验证工作，用户无需逐文件审批。

核心原则：**一部片子 = 一个明确工作目录 = 一张明确绑定的画布。** 普通画布可独立编辑；使用项目级本机 Agent 时必须有明确绑定。同名项目不能靠标题猜测。

## 2. 已确定的范围与方向

| 事项 | 已确定要求 |
| --- | --- |
| 正式产品 | 一个「小陈的画布」macOS App；保留个人分支和上游许可证声明 |
| 前端 | 保留 React / TypeScript 画布及现有创作界面 |
| 后端 | 使用 Rust，完成实际依赖的 Go API 迁移；新增 Agent 后端也使用 Rust |
| 本地数据 | 画布、素材、收藏、对话和项目状态可靠保存在本机，更新与迁移保留原数据 |
| App 账号 | 不恢复已移除的 App 登录、账号算力、云同步及云素材入口；历史记录保留 |
| AI 来源 | 原有用户自配 API，以及本机 Codex、Grok、Antigravity |
| 本机 AI 身份 | 沿用对应官方工具现有登录；不能擅自改成 API Key 计费来代替订阅接入 |
| 画布 Agent | 理解当前项目及素材，按用户目标完整执行创作操作、媒体生成和结果回填；用户手动修改后从最新状态继续 |
| 程序操作入口 | CLI / API / MCP 覆盖画布全部现有创作能力，与页面和侧栏共用操作、任务及保存机制，具体标准见 R9 |
| 人机共同编辑 | 用户与 Agent 操作同一张明确绑定的画布，双向可见最新内容、关系、素材与任务状态，防止旧状态覆盖新修改 |
| 普通终端 | 保留片子目录中的普通 Shell，供用户自行使用工具 |
| 实施方式 | 已授权修复、优化、迁移、整合、备份、安装和验收，持续推进，不重复询问常规步骤 |

本轮不扩展为多人协作云平台、账号计费平台、全新前端或其他操作系统发行版。第三方模型服务仍可联网；“本机 Agent”表示连接程序在本机，不表示模型离线运行。Node 页面服务与 Go 业务后端是不同职责，保留现有页面服务不等于 Rust 业务后端迁移失败。

## 3. 核心使用流程

1. 打开 App，找到真实存在的片子，能辨认同名项目和绑定目录。
2. 进入画布，恢复该片子的内容、视口和面板状态。
3. 用户通过侧栏或外部 Agent 表达目标、引用节点；Agent 经统一接口读取最新故事、资产、分镜和任务状态。
4. Agent 按实际故事要求、SOP 和资产状态创建、修改和整理内容，按用户授权提交媒体任务；缺少资产时先补齐。
5. 操作和生成结果直接回到正确节点，App 与各接口均能读取真实进度、结果和保存状态；原图可打开，音视频可播放。
6. 用户随时手动修改、替换素材或撤销；Agent 再次读取最新状态继续执行，遇到并发修改先解决冲突，不覆盖用户的新内容。
7. 失败、取消及中断后保留可核对的任务与结果，能够恢复工作；导出项目并在隔离的新项目中导入，素材、正文和关系仍完整可用。

## 4. 功能需求与通过标准

### R1 · 项目与绑定

- 首页、画布列表和实际存储中的有效项目保持一致；旧缓存不能把已删除项目伪装成已恢复或已同步。
- 同名项目可通过工作目录或绑定状态辨认；无绑定、重复绑定和失效绑定给出可操作提示。
- Agent 从绑定的片子目录启动，恢复对话时校验来源、项目与会话归属。
- 验收：新建、打开、重启、同名项目、旧缓存及历史删除场景逐一比对有效 ID；不得串画布。

### R2 · 保存与恢复

- 节点正文、位置、连线、素材引用与对话可持久保存；视口、缩放、面板状态也须按项目恢复。
- 显示实际保存状态。连接成功不等于编辑已保存，保存失败不能静默忽略。
- 保存失败、迟到响应或刷新不能用旧数据覆盖尚未保存的编辑；提供可恢复内容与重试路径。
- 验收：失败注入、乱序响应、快速连续编辑、重载、重启以及只有界面状态变化的场景。内容和状态与最后确认版本一致；失败可见且编辑可恢复。

### R3 · 素材显示与导入导出

- 统一处理已有素材来源，包括本地登记原图、浏览器素材及历史引用；显示、Agent 输入、导出均能解析正确来源。
- 原图保持比例与来源；图片显示成功、模型收到图片和导出包含原文件分别验证。
- ZIP 导出包含引用素材及必要映射。缺文件必须列出，不得默默漏图后提示完整导出成功。
- 新项目导入后建立正确引用；不能依赖原机器的旧地址或原项目 ID 才能打开素材。
- 验收：图片、历史图、视频、音频混合包往返；核对正文、关系、文件数量、字节哈希与播放/解码，覆盖缺失素材和中文名称。

### R4 · 画布交互与现有创作功能

- 保留节点创建/编辑/删除、连线、分组、目录筛选、平移缩放、撤销重做、素材收藏和引用。
- 保留图片、视频、音频、全景、导演台、提示词和已有工作流功能；迁移不能通过删掉仍使用的功能来获得“通过”。
- 上述创作操作同时提供 R9 规定的程序入口，供 Agent 直接执行，并保留用户手动编辑能力。
- 各模型设置分支可打开，不出现未定义变量等运行错误；协议不支持的能力明确展示。
- 图结构校验阻止新的无效端点。历史悬空连线先查恢复来源，无法确认时保留原记录和处理依据，不补造内容。
- 验收：覆盖上述交互、相关类型检查和模型设置分支；对真实历史项目做前后数据核对，媒体生成流程可用隔离替身验证。

### R5 · 画布侧栏 Agent

- 提供 API、Codex、Grok、Antigravity 来源，明确实际模型/连接状态；不同来源独立保存对话。
- 本机工具通过官方接口接入并沿用既有登录。Antigravity CLI 与 Gemini API/SDK 不混称。
- 支持流式回复、真实画布工具执行、会话恢复、停止及断线处理；工具结果和最终答复要与真实状态一致。
- 侧栏工具与外部 CLI / API / MCP 按 R9 共用画布操作和媒体任务能力；侧栏执行结果可由外部接口读取，外部操作也能在侧栏和画布继续处理。
- 引用图片时，支持图像输入的通道必须实际传入正确图片。通道不支持或解析失败时明确提示，不悄悄变成纯文字请求。
- 根据实际任务设置工具权限；已有扩展不是自动否决接入的理由，但不能把未经验证的权限隔离当作事实。
- 工具确认按序处理；取消、断线后旧确认失效；重复请求不能重复创建节点或提交媒体任务。
- 原生工具可能保存并展示其会话，需如实说明。画布与原生客户端切换时保持归属清晰，不将一端可见误当成两端状态自动完全一致。
- 验收：每个来源分别记录握手、工具调用、回复、恢复、取消、错误及附件能力。协议替身测试和真实模型测试分开，不能只以自然语言“完成了”作为工具成功证据。

### R6 · 上下文和创作阶段

- 按需提供选中节点、相关资产与目录索引，避免每轮无差别塞入整个画布和所有正文。
- 有可靠用量和窗口时显示上下文近似占用；已有 70% / 85% 提醒应验证。没有上限数据时只显示已知量，不编造百分比。
- 压缩状态与用量如实展示，累计计费 token、当前上下文和账号额度分别表达。
- 采用的 SOP 来源、版本或内容需可核对；阶段判断依据实际资产状态，重要定稿留在节点中。
- 验收：检查输入范围、用量换算及提醒/压缩事件；分别模拟资产不足和齐备，不把“正在生成”当作“已就绪”。

### R7 · 普通终端与性能

- 终端从正确片子目录启动，中文和流式输出稳定，调整面板或项目标题不无故重启 Shell。
- 停止或关闭仅回收自身启动的相关进程；高输出不能让画布长期失去响应。
- 优化持续平移的可见节点更新、大图连线计算、媒体加载及内存释放，使用测量决定具体实现。
- 验收：使用可复现、贴近真实原图和视频规模的隔离场景，记录硬件、素材规模、时长、帧耗时、长帧和内存；优化前后可比较，不以小图或假 DOM 数值冒充原生性能。具体性能目标由实施者依据基线设定并记录，无需逐指标请求批准。

### R8 · Rust 后端迁移

- 清点所有仍被桌面前端、任务和存储使用的 Go 接口，建立“调用方—旧职责—Rust 替代—验证结果”表。
- 在现有 Rust 工程中实现业务、数据库、文件与任务能力，保持必要接口兼容和数据语义；迁移期间可以分阶段运行。
- 已退出产品范围的账号/云端入口保持退出；旧数据可保留，不为其重新建设云后端。
- 最终正式 App 的活跃业务路径和打包启动流程不再依赖 Go sidecar；历史源码可作为参考保留，不能仍是运行所需组件。
- 验收：逐项接口与数据回归、数据库完整性、任务状态、异常恢复；检查安装包、启动日志和进程，实际运行所有迁移后的活跃功能。仅新增 Rust 文件或通过编译不算迁移完成。

### R9 · 完整程序操作与人机共同编辑

**目标：页面已有的画布创作能力，电脑通过 CLI / API / MCP 都能执行，并能与用户在同一张画布上持续迭代。** 外部 Agent 无需依赖用户代点页面来完成已授权的操作。

| 能力范围 | 必须提供的程序操作 |
| --- | --- |
| 读取现状 | 按需读取全部节点类型的正文、属性、关系、分组、素材及生成状态；获取可供对应模型使用的实际素材，不能只返回标题或缩略图描述 |
| 编辑内容 | 创建、修改、移动和删除各类节点，维护连线、分组与项目结构；可恢复删除及已有撤销、重做能力有对应入口 |
| 素材与项目 | 导入、引用、替换、收藏和导出已有支持的素材，保留原文件与历史引用；支持项目创建、明确绑定、打开、保存、导入导出和已有历史恢复能力 |
| 创作与生成 | 执行画布已有的图片、视频、音频、全景、导演台及工作流操作，使用用户选择的渠道、模型、参数和参考素材提交任务，并回填到正确节点 |
| 任务与结果 | 各入口均可查询任务标识、进度、成功结果、错误及取消状态；失败或中断后能够查回任务，避免重复提交或重复扣费 |

- 页面、侧栏、CLI、API 和 MCP 共用操作语义、任务记录及保存机制；各入口使用同一项目和节点标识。同一任务从任何入口发起，其他入口都能查到其状态和结果。
- Agent 修改后 App 更新对应内容；用户修改后 Agent 下一次读取获得最新状态。写入校验当前版本，发生冲突时返回最新状态和可处理原因，不用旧快照覆盖人工编辑。
- 能力与授权分开：媒体生成必须有可用的程序入口，并按用户已授予的范围执行；`paid_generation` 永久禁用、只能修改文字、只能查询任务均不作为产品完成标准。画布操作权限与 Agent 的文件、命令、网络权限分别设置，实际生效范围须验证。
- 建立“画布业务操作—页面—侧栏—CLI—API—MCP—验证证据”覆盖表，逐项记录已实现、待实现、已测与未测；仅某个入口可用时，其余入口仍记为缺口。新增画布创作能力同步补齐程序入口。
- 隔离测试先验证操作、状态和错误处理；生成的真实成功回执、素材及正式 App 表现另行验收。修改 PRD 或开放接口本身不代表已经完成产品验收。

验收必须包括以下完整过程，并逐项核对覆盖表：

1. 从绑定目录通过外部接口读取画布，创建和修改各类节点、素材引用、连线及分组；正式 App 显示与接口回读一致。
2. 用户在 App 中手动修改正文、位置和素材；Agent 读取最新状态后继续操作。并发、撤销、恢复和重启场景均保留正确内容。
3. 在授权范围内分别通过程序入口发起图片、视频和音频任务，取得真实任务回执及可打开或播放的素材，回填到指定节点；侧栏和页面可以继续编辑。覆盖查询、失败、取消、断线恢复及重复请求，取消等待不冒充远端任务已撤销。
4. 对侧栏、CLI、API、MCP 的同类操作核对一致结果；各本机 Agent 分别留下真实工具回执。隔离画布保存并重启后，正文、关系、素材与任务记录仍一致，原项目数据保持完整。

## 6. 交付与验收方法

任务由“完整运行检查与优化评估”负责整合、修复、Rust 迁移与最终安装；“Grok 与 Antigravity 接入”负责接入专项及其真实只读验证。双方协调共享文件、构建输出和 App 使用时段，避免同时安装或覆盖工作。

实施者自行分阶段完成：关键数据正确性修复、Agent 接入、Rust 替换、整体回归、正式安装与读回。阶段不是用户审批关卡；已授权工作持续推进。顺序可按依赖调整，不要求推倒重写或一次巨大改动。

每个 R1–R9 及 F1–F7 都要有实施状态、实际测试对象、证据和剩余问题。区分源码测试、故障注入、原生操作与真实第三方调用；未测、受外部条件阻塞不能标为通过。新发现的任务内缺陷按证据修复，不另起无限扩展的功能清单。

正式替换前备份当前 App 与实时业务数据；安装遵循现有唯一入口流程。更新后检查实际窗口、后台服务、节点/连线/对话/素材与配置，允许经记录的迁移变化，但不能丢失用户内容。回退资料保留可恢复状态。

完成标准是用户实际运行的 App 通过对应验收。报告需列出安装身份、迁移映射、数据读回、测试覆盖与未完成项；未完成关键能力时不得称为全部完成。

## 7. 授权与费用边界

用户已要求“全部都做，不要问我了，迁移也是”。必要代码、项目配置、依赖、备份、修复、数据迁移、构建、安装和重启无需逐项再次确认。

已授权的接入专项包括 Antigravity 仅画布侧栏 MCP 的窄许可，以及 Grok、Antigravity 各一条真实只读模型验收。执行状态由接入任务记录，不因新任务或新文档而重复消费；一条消息可能包含多次内部模型调用。

媒体任务的实际提交沿用用户在产品中的授权；本轮工程验收不默认授权批量付费生成、购买额度、擅自切换计费身份或对外发布。可用隔离数据和替身先完成其余验证。已明确的授权持续有效，只有新的实质性范围变化才需要用户决定。

上述专项验收次数和费用约束只适用于对应执行范围，不定义产品永久能力。按 R9 提供完整生成入口，在用户已有授权范围内执行；仅更换页面、侧栏、CLI、API 或 MCP 入口不应重复索要同一授权。

## 9. 已批准的七项优化

所有优化保留原文件和查看画质：预览也是判断创作效果，不能用低清替换、压缩原素材、删除文件换取性能。React / TypeScript 前端保留，新增后端使用 Rust。以下条目是交付要求，施工与验收分别记录，不能以源码完成代替正式 App 可用。

1. **拖动与连线**：只更新受影响路径；多选、分组、可见边界、增删及撤销重做后索引仍准确。
2. **长对话**：向上浏览不自动回底，底部跟随和主动跳转可用；按可见范围减少渲染及重复 Markdown，保留选字、复制、引用、重试、最终文本和历史浏览。
3. **素材内存**：不改变原图原视频字节和画质；节点、全屏、播放、导出及 Agent 使用中的地址不能失效。没有消费者及切项目时回收临时内存，重新进入可读取；不得删除持久历史引用的素材。
4. **Agent 上下文透明度**：区分发送前选择、实际送入及工具后读取，显示可核对的 SOP 来源和内容指纹。Codex 保留精简输入及 70% / 85% 提醒，其他来源没有可靠窗口时不显示推测百分比。
5. **跨重启版本历史**：持久版本清单、时间、可理解的差异预览和指定版本恢复，保留现有撤销重做。快照保留节点、关系、对话及未知兼容字段，素材采用稳定引用。恢复前版本必须保留，恢复经串行保存和版本冲突校验形成可追溯新修订；不得覆盖并发编辑、复活已删除项目、串绑定或重新发起历史生成任务。版本频率与空间有限，只管理本功能新增记录，不能清理用户原素材或既有恢复备份。先在副本验证重启、写入失败、并发、缺失素材和连续恢复，不回滚用户真实项目。
6. **资料库搜索分页**：数据库完成筛选和分页，保留旧接口排序、标签集合、多标签 OR、收藏、总数和分类语义。同一响应来自一致数据库快照。真实数据库只读副本及扩大规模测试覆盖中文、边界页和并发更新。
7. **取消与超时**：贯穿界面、页面代理和后端媒体读取，区分主动取消、连接失败、读取超时及服务退出。已提交远端的写入或付费生成，取消等待不代表撤销远端任务；不得因超时自动重复提交，有请求或任务 ID 时保留供核对。不得用统一短超时误伤长视频和流式对话；验证断开连接、慢响应、流读取、完整结束及后台资源回收。

性能比较记录环境、真实素材规模、时长及指标；隔离替身只证明逻辑，不冒充正式 App 效果。主整合任务统一构建、安装和原生验收；两优化任务交接共享文件，不并行安装。Antigravity 修复后的真实工具调用尚未复验，不得写成通过，也不追加真实付费模型或媒体调用。
