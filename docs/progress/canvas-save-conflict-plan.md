## 完成后的行为

1. 正常编辑自动保存；没有本机正文改动时，后台新版本可以更新到页面，并保留合理的个人视图状态。
2. 临时连接或写入失败保留草稿，可重试；版本冲突进入“待处理”状态，停止无效重发。显示明确、中文、项目内的处理动作。
3. 用户选择“使用最新版本”时，先确保当前未保存编辑有持久恢复副本，再重新读取并采用该项目当前最新文档与修订号。页面、撤销历史的适用范围、缓存、保存基线和待保存队列一起完成一致切换，后续编辑能正常保存。
4. 用户选择保留当前编辑时，可另存一个恢复副本，保持正文、关系、对话和素材引用；原项目的新内容仍保留。不能只是把旧草稿改成新修订号后覆盖原项目。
5. 提供足以判断的差异摘要：两边保存时间、节点及连线增删改数量、涉及的节点；不要求用户阅读原始 JSON。冲突期间允许暂不处理，编辑仍可恢复。
6. 仅在持有可信基线、能够证明改动互不冲突时，才可安全接续双方改动。优先利用既有操作语义；缺基线、同字段修改、删除或未知兼容字段有歧义时，保留两份并交给明确选择。不引入 CRDT、全新协作平台或通用合并框架。

## 实施步骤

### 1. 复现并明确保存状态

以隔离项目和现有真实模块重现旧草稿、Agent 外部更新、重试及重启循环。保存状态最少区分待保存、正在保存、已保存、可重试错误与版本冲突，保留结构化错误码，不靠中文字符串推断。沿用项目既有 store 和 Rust 模块，避免新增大型抽象。

### 2. 修复版本和队列的完整生命周期

- 同一项目串行保存，每次发送的正文与预期修订号对应；快速新编辑和迟到响应不能互相覆盖。
- 保存成功回执必须对应这次实际提交的结果。若 Rust 保存后再读会返回其他写入者的快照，改为在现有事务边界内返回正确文档及修订号，维持调用方兼容。
- 成功修订号正确进入内存与必要持久缓存；只有正文完全一致，才能将“已落盘但回执丢失”的恢复记录视为完成。
- 冲突项目停止旧请求的自动循环，并持久保留未解决状态。处理时取消或使该项目旧定时器、排队保存、迟到回执失效，不能影响其他画布。
- 使用最新版本的过程中若又发生外部更新或本机编辑，重新校验，不能用处理对话框打开时的旧快照宣布成功。
- IndexedDB 与 SQLite 无法共用单一事务；使用最小、可恢复的提交顺序和必要恢复标记，让中途失败或重启后能够继续正确恢复。任一步持久化失败都不能先清空唯一草稿或显示已保存。
- 已删除项目、缺失项目与单项目冲突分别处理，不复活已删项目，不让一张画布的失败阻断其余项目列表与保存。

### 3. 完成冲突处理界面和程序操作

沿用现有保存状态与条件横幅，普通错误仍可“重试”，版本冲突的入口改为可操作的处理流程。保持简洁中文和当前画布主题，不新增常驻工具栏。先更新 `docs/overview/ui-entry-inventory.md`，遵守入口数和动作唯一落位规则；涉及 Ant Design 时按 AGENTS.md 查对应版本文档。

选择最新版本、差异读取和安全保留副本需共享同一处理语义，依据 R9 检查必要的 CLI/API/MCP 支持；不要只实现界面按钮而留下保存逻辑分叉。最新版本选择是用户对指定项目的一次决定，不能扩展为所有画布永远丢弃本机编辑的默认策略。

### 4. 防止冲突恢复影响生成任务

之前重启后，修复前已排队的 `img-s06-78337b8b` 恢复执行，随后另一个 v2 画布出现生成授权弹窗；这属于已观察到的队列行为，不代表本轮授权新增付费调用。

核实保存恢复不会复制、重新提交或误恢复媒体任务；保留原 request/task ID、状态、项目与节点归属。正常的已授权任务恢复能力仍保留，未知远端结果先查询，不能重试创建。不能把旧草稿中的 loading 状态误当作新生成指令。测试使用隔离替身，不批准真实生成弹窗；不擅自取消用户其他任务。

### 5. 回归、安装与交付

至少覆盖以下验收：

- 两写入者使用同一旧基线；旧保存明确冲突，新内容不被覆盖。
- “使用最新版本”后继续编辑和保存，再重启，旧草稿不再夺回页面。
- 保留当前编辑为副本，两份内容、素材引用和项目归属都正确，任务不重复。
- 处理期间第二次外部更新、本机继续输入、迟到保存回执和快速连续编辑。
- 断网、写入失败、保存回执丢失、处理中断或重启，未保存内容可恢复且状态真实。
- 只有视口或面板变化，修订号正确接续；节点、连线、对话与未知字段保留。
- 单项目失败不影响其他项目；删除项目不会被旧缓存复活。
- 已排队或已提交的生成任务不重复提交，不新增付费调用。

复用现有测试和故障注入，先测试后构建；不要为低影响文案增加镜像实现式测试。检查并更新 `todo.md`、`pending-test.md` 和必要的 CHANGELOG；源码通过、安装完成、正式窗口通过分别报告。

正式安装沿用 `desktop` 的 `build:app` / `install:app` 与唯一应用入口规则，先备份现有 App、业务数据和 WebKit，保留现有已安装能力与配置。安装前核实真实画布、运行任务及其他开发工作，避免再次意外执行旧队列。以隔离画布完成正式窗口的冲突解决、继续编辑、重启和读回，再只读核对真实数据；不拿正式片子制造冲突或覆盖实验。

完成标准：用户可在 App 内解决冲突并持续保存，不再依赖手工修改 SQLite/IndexedDB；比较并交换保护、原内容与任务身份仍可靠，正式安装后的验收有证据。

## 工作区与授权边界
