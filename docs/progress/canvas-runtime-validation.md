## 阶段记录

## 音频实际输出

单应用 ScreenCaptureKit 实测通过。过滤器只包含 `com.chenyuxiaojin.infinitecanvas`，仅注册 audio 输出、关闭 microphone，采集 20 秒；点击隔离音频节点的原生播放按钮。1052 个音频缓冲成功写入，文件有效时长约 21.10 秒，其中有效测试信号 0.5 秒，与原 660 Hz 音频对齐后的归一化相关系数 0.99996686。未录制屏幕或麦克风。证据为仓库外 `audio-capture.log`、`audio-analysis.json`、`audio-correlation.json` 和 `app-output.m4a`。

结论仅覆盖本 App 的数字系统输出，不宣称物理扬声器声学验收。实现依据：[Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)。

## 性能基线

硬件 Mac16,6、arm64、36 GiB 内存。v2 在界面显示“已保存”并读回数据库后开始。场景为 20 张原图 265,738,573 字节、两段音视频 186,681 字节，50% 缩放。程序经现有视口发布函数进行 20 秒正弦往复平移，真实 WebKit 显示变化经截图确认；不是物理鼠标输入，也不是纯组件模拟。

| 场景 | 帧数 | 时长 ms | p50/p95/p99 ms | 最长 ms | 超过 50 ms |
| --- | ---: | ---: | --- | ---: | ---: |
| 有效首轮 | 1095 | 20016 | 17 / 22 / 24 | 904 | 6 |
| 同包暖态 | 1158 | 20011 | 17 / 21 / 22 | 366 | 3 |

存在偶发长帧，不能宣称稳定 60 fps 或优化提速。暖态与首轮差异仅是观察，不足以确定解码、GC 或其他具体根因。本轮没有压缩原图，也没有为指标更换预览质量。进程采样保存在仓库外 `perf-v2-rss.json`。

## 模型上下文调优

发现超过 16 项相关节点时，旧实现按画布存储顺序截取，当前选择和引用可能被历史批准资产挤掉。已改为当前选择、引用、历史批准资产的优先顺序，仍限制 16 项，不改变原画布。

100 个节点的隔离回归中，原输入 1,205,645 字节，旧/新精简结果均为 193,109 字节；旧实现丢掉当前选择和引用，新实现保留两者完整正文。新增回归验证去重、缺失 ID、连线边界和原输入不变，连同既有协议回归共 29 项通过。这个收益是输入相关性修复，不是模型响应速度或权重训练效果。

## 界面素材回收

实际 WebKit 中完成两轮退出/进入项目，包含原图完整预览、关闭预览、视频完整预览和播放。90 秒观测中，26.09 秒与 84.98 秒两次离开项目后，图片与音视频缓存均为 0 项、0 字节、0 租用，legacy/retired 为 0。重新进入后原图恢复为 20 项、265,738,573 字节，音视频 2 项、186,681 字节。两次重进后，从实际显示 URL 获取的 20 份图片字节与 SHA-256 序列均与基线相同（包含重复原图，共 16 个不同哈希）。第二次重进在 90 秒观测结束后，通过原图哈希回读验证。

没有强制 GC 或重启进程来制造释放结果。通过的是应用 Blob 租用层和重进可读性，不等同于 WebKit 解码缓存/RSS 立刻归零，也不代表所有长时场景无泄漏。记录见仓库外 `webkit-readback.json`、`lifecycle-rss.json`。

普通包另做三轮无哈希读取的进出测量：WebKit RSS 项目内/退出后分别约 1139.66/867.31、773.98/566.00、834.80/575.95 MiB。整个三轮在同一进程中完成，没有强制 GC，第二、三轮退出值没有持续增长；这支持有限场景下自然回收，不能外推长期所有操作无泄漏。诊断包的哈希读取阶段 RSS 曾升至 1406.78 MiB，单独保留为观测开销混杂数据。普通包证据为 `normal-lifecycle-marks.json` 和 `normal-lifecycle-rss.json`。

## 本轮真实模型调用

沿用既有本机登录，不改账号、模型或全局配置。正式 App 进程环境没有 OPENAI/XAI/GROK/GEMINI API 密钥；Codex `account/read` 只接受 ChatGPT；Grok 配置没有 model.api_key/env_key，使用 cached_token；Antigravity 未配置 Gemini API provider，也未开启信用额度超额设置。官方边界依据：[Codex 认证](https://learn.chatgpt.com/docs/auth)、[Grok 认证优先级](https://docs.x.ai/build/enterprise)、[Antigravity 认证](https://www.antigravity.google/docs/cli/install/)、[信用额度默认设置](https://www.antigravity.google/docs/cli/reference/)。

- Codex：正式 UI，gpt-6-astra，1 条真实请求成功，实际摘要工具 1 次，准确返回标题和 22 节点，原生上下文显示约 9%。
- Grok：正式 UI，grok-4.6，1 条真实请求成功，实际摘要工具 1 次，准确返回标题和 22 节点。
- Antigravity：第一次 UI 提交失败，已在该独立会话数据库定位为执行器构造错误：`unknown component: tool "call_mcp_tool" not found in registry`。仅有 user/error 两步，`gen_metadata` 为 0，无画布工具调用；不能算真实模型成功。

Codex 首次界面点击因隔离画布未绑定目录，在启动 CLI 前拒绝，未创建远程会话、未发送模型请求。之后仅为新测试画布通过官方 CLI 创建仓库外目录绑定，并增加新的目录登记，原目录绑定不变，再执行上面的唯一真实请求。该失败同时暴露界面丢弃 Rust 字符串错误的问题，已改为显示明确原错误，避免只显示“Agent 执行失败”。此提示修复已随最终普通包构建安装。

### Antigravity 执行器修复

官方自定义 Agent 规范将 `tools` 定义为显式允许的工具清单，`mcpServers` 用于配置 MCP 服务；文档没有明确证明 `tools: []` 时 MCP 工具仍会自动暴露。当前配置意图是保持内置权限为空，仅连接画布 MCP，实际工具暴露尚待验证。原配置中的 `call_mcp_tool` 不是有效内置注册名，初始化能成功，执行时才失败；`finish` 本身是有效内置工具，不能一并认定非法。现改成 `tools: []`，保留唯一画布 MCP、`inheritCustomizations: false`、禁用子代理与命令执行，不退回默认 Agent。6 项 Rust 接入回归通过，其中配置单测只验证生成内容，不能证明运行时工具注入。依据：[官方工具校验说明](https://antigravity.google/docs/subagents)、[MCP 配置说明](https://antigravity.google/docs/mcp)。

修复后已经完成唯一一次有根因依据的复验，正式普通包已安装。第二次 UI 提交产生 1 条模型生成，执行器错误消失，但只返回包含 `get_canvas_summary` 的 actions JSON 和正确标题/22 节点，没有实际画布工具调用。没有执行返回的 JSON 来补造工具成功。因此 Antigravity 仅通过模型文字回复，真实工具验收仍未通过。本轮合计两次 UI 提交：第一次 0 生成，第二次 1 生成；不再追加模型请求。

### Antigravity 工具暴露证据边界

实际运行时临时 Agent 配置已读回：内置工具列表为空、不继承自定义配置、不启用子代理、命令执行关闭，仅包含一个画布 MCP；未退回默认 Agent，未增加 Shell、文件或浏览器能力。证据见 `agy-active-profile-check.json`。

本轮会话数据库的生成元数据为 1 条，执行器元数据为 1 条。只读统计发现生成元数据含摘要工具名称，但没有 `tools/list`、`initialize`、`inputSchema` 或 `<mcp_servers>` 文本标记。名称也存在于输入 SOP 中，因此这些字符串既不能证明工具被原生注册，也不能证明未注册。当前 MCP 处理器没有保存 initialize/tools/list 访问日志；会话清理后临时诊断文件不再可读。本轮未获得可独立识别的模型原生工具定义清单，无法区分“没有暴露工具”和“已暴露但模型选择 JSON”。SOP 的 JSON 兼容指令只是待排查线索，不能认定根因。统计见 `agy-tool-exposure-audit.json`。

下一步需先补仅记录方法、工具名与数量的临时 MCP 握手观测，并核对官方 CLI 的实际注册工具清单；已有证据中未确认可独立完成这项核对且保证零生成的官方检查入口。确定暴露状态后，才安排另一次有明确调用预算的真实复验。本轮不为补证再发模型请求。
