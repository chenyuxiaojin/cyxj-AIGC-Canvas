# 本机原图生成链路补齐

## 根因与范围

媒体外置后，节点正文已改为 `local-ref:`，但节点生成的 `imageToDataUrl` 只读取 IndexedDB / HTTP 旧来源，将该引用交给 fetch 导致 `Load failed`。现场 `i-s00` 原图仍存在，1,563,039 字节，SHA-256 为 `1191e8da4b109ca086126ca2dc6f0dbad72010ddea768e0f333a1a318a99e145`，没有丢图。

另一问题是独立 CLI 生成借用了侧栏会话的操作版本号。现场命令关联保存把操作版本从 745 推进到 746，后续命令仍用 745，因此误报 `stale_revision`。该内部关联写入不等于用户手动改图，也不能笼统归因于媒体迁移。

原生验收进一步发现桌面窗口隐藏后暂停结果轮询，任务已提交却不能在后台收回结果。此轮同时修正桌面端轮询，继续查询既有任务，不重新提交生成。

连续外部修改验收还复现了第三处断点：已保存视频在预览时使用 blob URL，页面接收外部更新却比较未经规范化的节点，把临时预览地址当作未保存编辑并阻塞队列。原始深比较还会把 JSON 保存时省略的 undefined 字段视为变化。保存与接收检查现复用 buildCanvasStructureOperations，与持久协议采用相同的稳定引用和字段语义；真实内容修改仍阻止覆盖。

## 修复

- 参考图携带明确项目 ID，通过已有 Rust `read_canvas_local_media` 读取原字节，只在模型请求边界临时转换。已解析的参考图直接复用，不重复读盘；节点和生成历史仍保存稳定 storageKey。
- 覆盖普通图、首尾帧、Kling 图片主体、全景/角度/图像编辑、历史参考图重试；音视频文件提交同样按项目读取本机原文件。模型明确要求公网 URL 的音视频主体输入保持明确报错，不伪造可用地址。
- 每条持久命令单独捕获操作版本，不读取或更新另一个侧栏会话的基线。命令文档 SHA 校验与真正的并发 `stale_revision` 拒绝仍保留。
- 保存及接收外部版本时忽略运行时媒体地址和序列化省略的空字段，生成之后的下一条外部命令无需重启接续。
- 桌面端后台继续查询已提交任务；普通浏览器隐藏时仍暂停，卸载页面正常清理定时器。
